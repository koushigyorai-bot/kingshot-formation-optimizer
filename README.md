# Kingshot Formation Optimizer

所持英雄・装備・兵力から、Kingshot の各イベントで最もスコアの高い英雄編成と兵種比率を算出する Web ツールです（非公式）。

- Next.js 14（App Router）+ TypeScript + TailwindCSS
- 保存先: localStorage（`kingshot_user_data_v1`）。repository パターンで Supabase に差し替え可能
- クローラー: `fetch` + `cheerio`。Route Handler `/api/crawl` 経由で CORS を回避

## セットアップ

```bash
npm install
npm run dev        # http://localhost:3000
npm test           # 単体テスト（node:test + tsx）
npm run typecheck
npm run build
```

Node.js 18.18 以上（推奨 20 以上）。

## 画面

| パス | 内容 |
| --- | --- |
| `/setup` | 英雄（カード形式・世代バッジ）、領主装備、兵士、研究・その他のバフ（研究・役職スキル・VIP）、保存・入出力 |
| `/optimize` | イベント選択（集結・熊狩り・駐屯・競技場・討伐） → 最適編成トップ 10、兵種比率、計算の内訳、計算の前提 |
| `/data` | 4 サイトのクロール、取得レポート、情報源どうしの食い違い、英雄マスター一覧 |

| 4 | kingshottools.pro | ファンサイト | 世代・兵種の照合のみ（紹介文に公式と矛盾する記述があったため数値は採用しない） |
| 5 | grindnstrat.com | 攻略ブログ | 2026-10-25 時点で Kingshot 記事なし。WordPress REST API で記事を検索し、見つかればティア・比率を抽出 |

- 同じ項目で値が食い違う場合は優先度の高い方を採用し、`/data` の「食い違い」に一覧表示します。
- 排外主義的・差別的な思想を流布するサイトは `src/lib/master/sources.ts` の `flagged: true` でマークでき、UI に警告を出したうえで取得・マージの対象から外します。現在の 4 サイトにこのマークは付けていません。

### クローラーの行儀

- robots.txt を取得し、Allow / Disallow（最長一致）と Crawl-delay を守ります。
- 同一ホストには 1.5 秒以上（Crawl-delay が長ければそちら）の間隔を空けて 1 件ずつ取得します。
- 本ツールを名乗る User-Agent を送ります。公開するときは `CRAWLER_USER_AGENT` 環境変数で連絡先を入れてください。
- 同じサイトへの再取得は 10 分空けます（開発環境のみ `force: true` で解除可）。
- 取得した文章は保存せず、数値・英雄名・比率だけを構造化して保持します。
- 各サイトの利用規約は変わることがあります。公開・定期実行の前に規約を確認してください。

サーバーレス環境では実行時間制限があるため、`/data` 画面は 1 サイトずつ POST します。公式 Wiki は約 40 ページあり、1 回に 1 分以上かかります。Vercel の Hobby プランなど 60 秒制限の環境では、ローカルで `npm run dev` して取得し、結果（localStorage に保存されるマスターデータ）を使ってください。

## データ更新の結果の保存と共有

「データ更新」画面で取得した結果は、次の 3 か所に保存できます。

| 保存先 | 用途 |
| --- | --- |
| ブラウザ（localStorage: `kingshot_crawl_snapshot_v1`） | 自動。ブラウザのデータを消すと失われる |
| JSON ファイル（「JSON に書き出す」） | バックアップ・別の端末への移行。「JSON を読み込む」で復元 |
| `public/master-data.json` | リポジトリに置くと、公開サイトを開いた全員に同じデータが配られる |

保存するのはマージ済みのデータではなく、クロールした生の結果です。読み込むたびに同梱の初期データと重ね直すので、アプリ側で初期データやスキル文の解析を直すと、保存済みのデータにも反映されます。ブラウザの保存と `public/master-data.json` の両方がある場合は、取得日時の新しい方を使います。

## 計算式

仕様書の式をそのまま骨格にしています。

```
基礎戦闘力         = Σ(英雄基礎ステータス × レベル補正 × 星補正) + 装備ボーナス + 領主装備ボーナス
イベント補正後戦闘力 = 基礎戦闘力 × (1 + スキルバフ合計) × 兵種相性補正 × ウィジェットバフ
総ダメージ期待値     = イベント補正後戦闘力 × Lethality × Squad Attack × クリティカル期待値
```

実装上の解釈（`src/lib/calculator/calculator.ts` 冒頭にも記載）:

1. Expedition 系（集結・熊狩り・駐屯）は兵種ごとに計算して合算します。英雄の Expedition ステータス（%）は同じ兵種の部隊に掛かります。
2. 兵種比率を最適化できるよう、基礎戦闘力に兵数の項 `sqrt(兵数 × 少ない側の兵数)` を掛けます（kingshot.wiki の熊狩り解析に出てくる army factor）。
3. スキルバフ合計は Lethality・Squad Attack との二重計上を避け、与ダメ増加・集結攻撃・敵被ダメ増加だけを集計します。
4. 確率発動スキル（例: 40% の確率で与ダメ +50%）は期待値（+20%）に換算します。
5. 対人の集結は反撃を受けるため、`攻撃^(1-w) × 生存^w`（w = 0.35）で生存力も加味します。駐屯は w = 0.6、熊狩りは反撃が無いので w = 0 です。
6. Conquest 系（アリーナ・征服）は英雄自身のステータスと Conquest スキルで、`総火力 × sqrt(前衛の実効 HP)` を評価します。推奨外の兵種を置いた枠には補正を掛けます。

出典の無い係数（レベル補正、星補正、装備 1Lv あたりの効果など）は `src/lib/calculator/config.ts` に `assumption: true` として集約し、`/optimize` 画面の「計算の前提」に一覧表示しています。**スコアは編成どうしを比べるための指数で、ゲーム内のダメージ値とは一致しません。**

### 探索方法

- **集結リーダー（3 人）**: 公式 Wiki によれば、自分で開いた集結では 3 人全員のスキルが有効で、隊長枠に誰を置いても同じです。そのため順列 P(n,3) ではなく組合せ C(n,3)（= P(n,3) / 6）を全探索します。「兵種ごとに 1 人」をオンにすると 歩×騎×弓 の直積を全探索します。表示順は、参加時に効く 1 番目のスキルが強い英雄を左端にしています。
- **集結に参加（ジョイナー）**: 先頭英雄の 1 番目の Expedition スキルだけが反映されるため、英雄単位で評価します。
- **アリーナ（5 人）・征服（3 人）**: 位置が意味を持つので順列で評価します。探索空間が上限（既定 20 万）を超えたら、位置グループ（前衛・側面・後衛）ごとに上位 8 人へ絞ってから全探索します。それでも候補が作れない場合は遺伝的アルゴリズム（固定シードで再現可能）に切り替えます。
- **兵種比率**: 上位候補ごとに、イベント・世代別のプリセットから ±15% の範囲を 1% 刻みで探索します。兵の在庫が足りない兵種は在庫で頭打ちになり、その旨を内訳に表示します。

## 初期データ（シード）の状態

- 英雄 37 人の世代・兵種・レアリティは公式 Wiki の英雄一覧で確認済みです。
- ステータスとスキルを公式 Wiki で確認できたのは Amadeus・Gordon・Chenko の 3 人です。Howard はファンサイト、Helga・Fahd・Olive などの一部ステータスは BlueStacks の Gen1 解説、Petra・Zoe・Vivian の Conquest スキルは kingshotmastery.com を出典にしています。
- それ以外は推定値（Gen1 レジェンド 200.16% から 1 世代あたり約 1.2 倍）で、UI では「推定値」バッジを付けています。`/data` でクロールすると公式値に置き換わります。

## Supabase への移行

`src/lib/repository/supabase.example.ts` にテーブル定義と実装例があります。`UserDataRepository` を実装し、`src/lib/repository/index.ts` の `createRepositories()` で差し替えるだけで、UI と計算ロジックは変更不要です。

## 既知の制限

- ゲーム内部の計算式・係数の多くは非公開のため、スコアは近似です。「研究・その他のバフ」の上級者向け欄で兵種別の合計値を直接指定することもできますが、英雄分の二重計上に注意してください。
- T6 以外の兵のステータス、VIP・領主装備の段階ごとの効果量は確認できていません（前提一覧に記載）。
- 英雄の画像は使用していません（頭文字と兵種色のプレースホルダー）。
- クローラーは各サイトの HTML 構造に依存します。構造が変わると取得レポートに警告が出て、シード値で計算を続けます。
